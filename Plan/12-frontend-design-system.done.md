# 12. Дизайн-система фронтенда

**Статус:** done
**Обновлено:** 2026-08-12
**Проект:** frontend
**Зависит от:** 03

## Цель

Настроить визуальную основу: тему, layout-каркас под мобильный экран,
переиспользуемые компоненты (кнопка, карточка/плитка, bottom sheet, слайдер).

## Детали

1. Tailwind config — тема под тёмный/светлый режим (мобильные пользователи
   часто настраивают устройство в разных условиях освещения — учесть
   `prefers-color-scheme`), безопасные отступы под "чёлку"/системные жесты
   (`env(safe-area-inset-*)`), крупные тач-таргеты (мин. 44×44px — iOS HIG,
   разумный ориентир и для Android).
2. Базовые компоненты через shadcn/ui: `Button`, `Slider` (для громкости и
   задержки), `Sheet`/`Drawer` (vaul) для мобильных модалок снизу экрана,
   `Dialog` для подтверждений (удаление трека/сценария — деструктивные
   действия всегда с подтверждением, по аналогии с "Очистить store" в
   audio_test).
3. Анимации (Framer Motion) — на что тратить анимационный бюджет в первую
   очередь:
   - Появление/исчезновение плиток (layout animations при фильтрации по
     группе).
   - Drag-переупорядочивание шагов сценария (`Reorder` из Framer Motion).
   - Переход между экранами wizard'а (треки -> сценарий -> активация) —
     slide-транзиции, ощущение "шагов", а не резких скачков.
   - Не переусердствовать — анимации должны быть быстрыми (~150-250ms),
     устройство мобильное, лишняя задержка раздражает.
4. Иконки — `lucide-react` (идёт в комплекте со стандартной установкой
   shadcn/ui, консистентный набор, не нужно тащить отдельную библиотеку).

## Открытые вопросы

- Нет — это в основном технические решения, которые беру на себя, реализация
  открыта для правок по вкусу после первых экранов.

## Критерии готовности

- Каркас темы + 3-4 базовых компонента собраны и провизуализированы на тестовой
  странице (Storybook не нужен для проекта такого размера — просто демо-роут).

## Как реализовано (частично — сделано вместе с планом 13)

- Тема light/dark через CSS-переменные (`index.css`, `tailwind.config.js`,
  darkMode: "class") — была уже с bootstrap (план 03), доработано:
  `main.tsx` включает класс `.dark` по `prefers-color-scheme`, без ручного
  тумблера (мобильное устройство, пользователь настраивает на уровне ОС).
- Базовые компоненты (`src/components/ui/`) — написаны вручную по образцу
  shadcn/ui (не скопированы как есть из `Level-compact` — там часть в
  `.jsx`, здесь проект строго на TS): `Button`, `Card`, `Input`, `Badge`,
  `Skeleton`, `Dialog` (на `@radix-ui/react-dialog`, новая зависимость).
  Провизуализированы не на отдельном демо-роуте, а прямо в рабочем экране
  треков (план 13) — так сразу видно, работают ли они в реальном контексте.
  Минимальный тач-таргет 44px — на `Button`/`Input` (`h-11`).
- **Не сделано:** `Slider` (нужен для громкости/задержки — понадобится в
  плане 14), `Sheet`/`Drawer` (vaul уже в зависимостях, не использован),
  Framer Motion анимации (layout-анимации плиток, drag-переупорядочивание,
  переходы между экранами) — откладываю до появления второго экрана (план
  14/15), пока анимировать нечего (переход из/в один существующий экран).

## Обновление — цвет + базовые анимации (по запросу пользователя)

Объём согласован явно: сначала цвет + базовые анимации, `Slider`/`Sheet`/
drag-переупорядочивание — отдельным проходом позже.

- **Тема** — тёплый/амбиентный акцент (терракотовый/оранжевый,
  `hsl(24 75% 50%)` в light, `hsl(24 80% 58%)` в dark) поверх тёплой
  нейтральной базы, не холодный серый дефолт shadcn. Оба режима (`:root`/
  `.dark`) в `index.css`, весь набор CSS-переменных (`--background` …
  `--ring`) пересчитан заново под тёплые оттенки, не только `--primary`.
- **Анимации (Framer Motion, уже было в зависимостях, наконец использован)**:
  - Сетки треков/сценариев — `motion.div` с `layout` (плавный reflow при
    фильтрации/сортировке) + `initial`/`animate` (fade+scale при появлении
    новых карточек).
  - Переключение вкладок "Треки"/"Сценарии" (`App.tsx`) — fade+slide на
    контейнере, `key={tab}` пересоздаёт анимацию при каждом переключении.
  - Баннер активного сценария — fade+slide вниз при появлении.
  - **Осознанно без `AnimatePresence`/`exit`** — в отличие от плана-черновика
    (там ожидалось "появление/исчезновение"), exit-анимации не сделаны:
    `AnimatePresence` держит элемент в DOM во время исчезновения, что
    ломает синхронные проверки в тестах (`not.toBeInTheDocument()` сразу
    после действия) без дополнительного мока `framer-motion`. Только enter+
    layout — этого достаточно для "базовых" анимаций, exit можно добавить
    отдельно с мокой в `test/setup.ts`, если понадобится.

`npm run build`/`test:run` (45/45, без единого мока framer-motion) — зелёные.

## Обновление 2 — Slider + Drawer (по запросу пользователя)

- **`Slider`** (`@radix-ui/react-slider`, новая зависимость) —
  `components/ui/slider.tsx`, тач-таргет 44px на `Thumb` (визуальный "бегунок"
  меньше, центрирован внутри). Используется для громкости шага в
  `ScenarioEditor` (задержка осталась числовым полем — по плану 14 слайдер
  предполагался только для громкости).
  **Грабли:** `role="slider"` реально у `SliderPrimitive.Thumb`, не у `Root` —
  если передавать `aria-label` в `Root` (как в `Dialog`/`Drawer`), доступное
  имя у слайдера остаётся пустым, `getByRole('slider', {name})` в тестах не
  находит элемент. Нужно явно прокидывать `aria-label` на `Thumb`.
- **`Drawer`** (vaul, уже был в зависимостях, наконец использован) —
  `components/ui/drawer.tsx`, `TrackImagePicker` переведён с `Dialog` на
  `Drawer` (bottom sheet) — так и предполагал план 13 ("долгий
  тап/кнопка... открывает bottom sheet"). `ConfirmDialog` остался на
  `Dialog` — план 12 явно требует `Dialog` именно для подтверждений.
- **jsdom-грабли (оба компонента):** ни `ResizeObserver`
  (`@radix-ui/react-use-size`), ни Pointer Capture API
  (`setPointerCapture`/`releasePointerCapture`/`hasPointerCapture`, нужны
  vaul для drag-жестов) не реализованы в jsdom — без полифиллов тесты падали
  с `ReferenceError`/`TypeError` (последнее — необработанные async-исключения,
  сбивавшие соседние тесты, не только свой файл). Добавлены заглушки в
  `src/test/setup.ts` — теперь общий полифилл для всех будущих Radix/vaul
  компонентов, не нужно повторять при следующем использовании.

## Обновление 3 — drag-переупорядочивание, exit-анимации, единицы времени

Последние три пункта из первоначального списка "не сделано" — закрыты.

- **Drag-and-drop** (`Reorder.Group`/`Reorder.Item`, `framer-motion`) —
  `components/ScenarioStepRow.tsx` (вынесен из инлайн-`.map()` в
  `ScenarioEditor` — нужен свой `useDragControls()` на каждый шаг, хук
  требует компонент верхнего уровня). Тащить можно только за отдельную
  ручку (⠿, `GripVertical`), не за всю строку — иначе перетаскивание
  перехватывало бы клики по инпутам/слайдеру внутри (`dragListener={false}`
  на `Reorder.Item` + `dragControls.start()` на `onPointerDown` ручки).
  Кнопки вверх/вниз удалены, это их полная замена.
- **`exit`-анимации** (`AnimatePresence`) — теперь на сетках треков/сценариев
  и на баннере активного сценария. Стало возможно только после мока
  `framer-motion` в тестах (см. ниже) — без него `AnimatePresence` держит
  элемент в DOM во время исчезновения, что ломало бы синхронные
  `not.toBeInTheDocument()` в существующих тестах.
- **Единицы времени** — `components/DurationInput.tsx`: числовое поле +
  `<select>` (сек/мин/ч). Юнит — чисто локальный UI-стейт (какой единицей
  СЕЙЧАС отображается и вводится значение), хранится всегда в секундах
  (формат сценария на устройстве, план 07) — переключение единицы само по
  себе не меняет сохранённое количество секунд. Единица по умолчанию
  автоопределяется по значению (кратно 3600 → часы, кратно 60 → минуты,
  иначе секунды). Заменил числовые поля для `startDelaySec` и
  `delayAfterPrevSec` (в т.ч. для пауз).
- **Мок `framer-motion` в `src/test/setup.ts`** — синхронный passthrough без
  реальных анимаций: `motion.*` (через `Proxy`, любой тег), `AnimatePresence`
  (рендерит детей сразу), `Reorder.Group`/`Reorder.Item` (обычные элементы,
  `as`-тег уважается), `useDragControls` (no-op). Реальный drag-жест в jsdom
  всё равно не воспроизвести (нет настоящих pointer-move дельт) — тесты
  проверяют рендер/данные, не сам жест перетаскивания.

  `App.tsx` наследует отступ от паддинга body.
