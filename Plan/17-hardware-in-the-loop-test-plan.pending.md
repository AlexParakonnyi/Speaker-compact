# 17. План проверки на реальном железе

**Статус:** pending
**Обновлено:** 2026-07-27
**Проект:** device + frontend
**Зависит от:** все остальные пункты (сквозной чеклист, не блокирует их, но
подводит итог)

## Зачем отдельный пункт

Опыт `audio_test` показал: чистая компиляция ничего не гарантирует на
реальном железе — отсутствие общей земли, неверное выравнивание бит
микрофона, гонки между задачами, разряд AP-сети — всё это всплывало только
при тестировании на устройстве, иногда через несколько сессий отладки.
Здесь ставки выше (deep sleep, батарея) — нужен явный чеклист, не полагаться
на "наверное заработает".

## Чеклист (заполняется по мере готовности соответствующих пунктов)

- [ ] Базовая сборка (план 01) — `pio run` зелёный на реальном борде, прошивка
      заливается, `Serial` лог читается.
- [ ] SD-карта монтируется, список треков корректный (план 04).
- [ ] Группы создаются/сохраняются, переживают перезагрузку (план 05).
- [ ] Фото трека грузится с телефона (все три источника: буфер/камера/файл),
      отображается после перезагрузки устройства (план 06).
- [ ] Сценарий с 3+ шагами, разными задержками и громкостью проигрывается
      корректно от начала до конца (план 08).
- [ ] AP поднимается, фронтенд открывается на телефоне по `192.168.4.1`
      (план 09).
- [ ] Активация: AP гарантированно отключается после ответа фронтенду, не
      раньше (план 10) — проверить, что телефон успевает увидеть
      подтверждение перед потерей соединения.
- [ ] Deep sleep: устройство просыпается точно к следующему событию
      (замерить фактическое время, сравнить с ожидаемым — допустимый дрейф
      RTC-таймера ESP32 нужно эмпирически определить).
- [ ] Кнопка будит устройство из глубокого сна мгновенно, независимо от
      таймера, возвращает в режим AP (план 11).
- [ ] Состояние сценария переживает цикл сон/пробуждение (несколько шагов
      подряд, не только один).
- [ ] **Замер реального энергопотребления** (USB-мощность-метр или мультиметр
      в разрыв питания) в режимах: AP активен / CPU активен без Wi-Fi / deep
      sleep — подтвердить, что deep sleep действительно даёт ожидаемый
      выигрыш, а не съедается чем-то (например, недовыключенной периферией).
- [ ] Полный E2E-флоу с реального телефона: открыть плитки -> прикрепить
      фото -> собрать сценарий -> активировать -> дождаться срабатывания ->
      вернуть в настройку кнопкой.
