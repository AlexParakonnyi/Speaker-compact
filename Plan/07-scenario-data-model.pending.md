# 07. Модель данных сценария

**Статус:** pending
**Обновлено:** 2026-07-27
**Проект:** device
**Зависит от:** 04, 05

## Цель

Спроектировать и сохранить формат "сценария" — набора треков с индивидуальной
задержкой и громкостью, плюс общая задержка перед стартом всего сценария.

## Детали

1. Предлагаемая схема `/scenarios/<name>.json`:
   ```json
   {
     "name": "Вечерний",
     "startDelaySec": 600,
     "loop": false,
     "steps": [
       { "file": "track1.mp3", "delayAfterPrevSec": 0, "volume": 0.8 },
       { "file": "track2.wav", "delayAfterPrevSec": 30, "volume": 1.0 }
     ]
   }
   ```
   - `startDelaySec` — задержка перед началом сценария целиком (то, что
     пользователь "устанавливает перед активацией" по ТЗ).
   - `delayAfterPrevSec` на каждом шаге — пауза после окончания предыдущего
     трека перед началом этого (для первого шага — пауза после
     `startDelaySec`). Это и есть "задержка на каждый файл" из ТЗ.
   - `volume` на шаг — множитель громкости конкретно для этого трека
     (переиспользует `speakerWrite()`/`playbackVolume`-подобный механизм из
     audio_test, но per-track, не глобальный).
   - **`loop`** (подтверждено) — флажок в интерфейсе редактора сценария
     (план 14), по умолчанию `false`. Если `true` — после последнего шага
     сценарий начинается заново с первого (без повторной `startDelaySec` —
     она только перед самым первым стартом; пауза перед повтором = обычная
     `delayAfterPrevSec` первого шага). Если `false` — доигрывает и уходит в
     режим ожидания реактивации (см. план 11 — не автовосстанавливается,
     нужна ручная активация через AP).
2. API:
   - `GET /api/scenarios` — список сохранённых сценариев.
   - `POST /api/scenarios/save` — создать/обновить.
   - `POST /api/scenarios/delete`.
   - Активация — отдельный пункт (план 10), не часть CRUD.
3. Ограничение на размер сценария (макс. число шагов) — держать в разумных
   пределах (десятки, не тысячи шагов) с учётом ограниченной RAM устройства
   при разборе JSON в память.

## Открытые вопросы

- Схема выше — предложение Claude Code по мотивам ТЗ, детали (`delayAfterPrevSec`
  vs абсолютное время от старта и т.п.) можно скорректировать при первой
  реализации плана 08, если на практике окажется неудобно.

## Критерии готовности

- CRUD сценариев (включая `loop`) работает и переживает перезагрузку.
