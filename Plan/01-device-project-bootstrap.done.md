# 01. Инициализация проекта устройства

**Статус:** done
**Обновлено:** 2026-07-29
**Проект:** device
**Зависит от:** —

## Цель

Поднять `device/` как рабочий форк `PlatformIO/audio_test`: та же файловая
структура и библиотеки, но без всего, что относится к микрофону, плюс
задел под новые модули (`scenario`, `power`, группы).

## Детали

1. Заменить `platformio.ini`: борд под ESP32-S3-N16R8 (не текущий
   `esp32-s3-devkitc-1` — уточнить точное имя борда в PlatformIO или собрать
   как generic ESP32-S3 с ручными флагами `board_build.arduino.memory_type`
   под Octal PSRAM/16MB flash — зависит от точной платы, см. пункт 02).
   `board_build.filesystem` — не нужен (SD-карта, не LittleFS/SPIFFS для
   основного хранилища; но фронтенд-статику тоже кладём на SD — см. план 16,
   не на LittleFS).
2. Скопировать из audio_test и адаптировать:
   - `global.h` — общее состояние. Убрать всё микрофонное (нет RECORDING).
   - `storage.h/cpp` — SD_MMC, WAV-заголовки (нужны только на чтение —
     воспроизведение, не запись), список файлов.
   - `speaker.h/cpp` — без изменений по сути, переносится как есть.
   - `codec.h/cpp` — MP3/AAC декодер, переносится как есть (актуально и тут).
   - `servers.h/cpp` — HTTP API, переписать под новый набор эндпоинтов
     (список появится по мере реализации пунктов 04-11).
3. Явно НЕ переносить: `mic.h/cpp`, всё про `micTask`, `micMutex`,
   `liveListenActive`/`liveTalkActive`, WebSocket-эндпоинт `/ws` (если он не
   понадобится для чего-то другого — переиспользовать по необходимости для
   live-статуса из фронтенда, обсудить отдельно, не блокирует этот пункт).
4. `recorder.h/cpp` из audio_test переименовать в `player.h/cpp` — в этом
   проекте нет записи, только воспроизведение по сценарию. VAD-логика и
   `MIN/MAX_SEGMENT_MS` — не переносить (это было про нарезку записи).
5. Убедиться, что чистая сборка (`pio run`) проходит на пустом скелете, прежде
   чем переходить к следующим пунктам.

## Открытые вопросы

- Точное имя PlatformIO board id под ESP32-S3-N16R8 — решено использовать
  тот же `esp32-s3-devkitc-1`, что и в audio_test (generic-профиль, без
  привязки к N16R8-специфике); сборка зелёная на этом профиле.

## Критерии готовности

- `pio run` зелёный. ✅ (минимальная версия: global/storage/speaker/codec/
  player/network/servers/main — собирается чисто, RAM 18.2%, Flash 28.2%)
- Структура файлов совпадает с описанной в `CLAUDE.md` §4.1. ✅
- Ничего микрофонного в дереве исходников. ✅
- Из плана 16 (деплой фронтенда) реализован минимум: `/api/deploy-file` +
  `/api/upload-audio` через raw-body (`ArBodyHandlerFunction`), `sdMutex`

  сервер уже готов его принять.
