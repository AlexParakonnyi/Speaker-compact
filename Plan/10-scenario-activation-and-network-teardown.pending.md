# 10. Активация сценария и отключение сети

**Статус:** pending
**Обновлено:** 2026-07-27
**Проект:** device + frontend
**Зависит от:** 07, 08, 09

## Цель

Флоу активации: пользователь выбирает/настраивает сценарий, задаёт задержку
перед стартом, жмёт "Активировать" — устройство гасит AP/Wi-Fi и уходит
выполнять сценарий (план 08) через deep sleep (план 11).

## Детали

1. `POST /api/scenarios/activate` — `{name, startDelaySec (опционально,
   перекрывает сохранённое значение в сценарии на этот конкретный запуск)}`.
2. Обработчик (через `pendingCmd`, не напрямую из HTTP-хендлера):
   - Сохранить состояние сценария (план 08) — `scenarioActive = true`,
     `currentStepIndex = 0`, `nextEventUnixTime = now + startDelaySec`.
   - Отправить HTTP-ответ фронтенду **до** отключения сети (иначе телефон не
     получит подтверждение) — короткая задержка (пара секунд) перед
     `WiFi.softAPdisconnect()`/`esp_wifi_stop()`, чтобы ответ гарантированно
     ушёл.
   - Показать на фронтенде явное предупреждение "точка доступа сейчас
     отключится, повторное подключение — через кнопку на устройстве" — важно
     для UX, чтобы не выглядело как зависание.
3. Собственно отключение Wi-Fi/AP и первый уход в deep sleep — см. план 11.

## Открытые вопросы

- Нет, стыкуется с уже принятыми решениями.

## Критерии готовности

- Нажатие "Активировать" на фронтенде надёжно приводит к отключению AP и
  началу отсчёта задержки на устройстве (проверяется по логам Serial при
  первых тестах, см. план 17).
