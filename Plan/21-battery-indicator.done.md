# 21. Индикатор заряда батареи

**Статус:** done (делитель откалиброван по факту; диапазон под 1S Li-ion — ждёт реальной батареи)
**Обновлено:** 2026-08-11
**Проект:** device + frontend
**Зависит от:** —

## Цель

Показать пользователю приблизительный заряд батареи (напряжение + процент) —
запрошено пользователем по ходу работы над сценариями, до этого был только
зарезервирован пинаут ADS1115 (`CLAUDE.md` §3, §7 "Открытые вопросы").

## Решение (согласовано с пользователем)

- Только напряжение/процент, без детекции зарядки по тренду (как в
  `Level-compact/BatteryMonitor.cpp`) — не нужно на данном этапе, можно
  добавить позже, если понадобится.
- 1S Li-ion/LiPo (3.0–4.2В), линейная аппроксимация напряжение→процент —
  реальная разрядная кривая нелинейна, но для "прикидочного" индикатора
  этого достаточно.

## Калибровка делителя (сделано 2026-08-11)

Изначальное предположение `DIVIDER_RATIO = 2.0` (симметричный 1:2) было
неверным: UI показывал 7.54В при реальных (измеренных мультиметром) 5.1В на
входе. Источник на момент калибровки — USB-зарядка телефона (5В), не
реальная батарея (см. §7 `CLAUDE.md`), но это не мешает калибровке самого
коэффициента — он свойство резисторов на плате, не зависит от того, что к
ним подключено.

Пересчёт: `channelVoltage` (то, что физически видит канал 0 ADS1115,
не зависит от `DIVIDER_RATIO`) = 7.54 / 2.0 = 3.77В. `actualRatio` = 5.1 /
3.77 ≈ **1.353** — подставлено в `device/src/battery.cpp`.

**Если делитель на плате физически изменится** (перепаяют резисторы) —
пересчитать заново той же формулой: `actualRatio = реальное_напряжение /
(текущее_показание_UI / текущий_DIVIDER_RATIO)`.

**Что ещё не откалибровано:** `BATTERY_EMPTY_V=3.0`/`BATTERY_FULL_V=4.2`
(диапазон 1S Li-ion для расчёта процента) — рассчитаны на реальную батарею,
которой пока нет (см. выше, питание от USB 5В). При 5.1В на входе процент
будет упираться в 100% (`constrain()` в `updateBatteryReading()`) — это
ожидаемо, не баг, просто 5.1В выше "полного" порога 4.2В. Пересчитывать
смысла нет, пока не подключат реальную батарею.

## Как реализовано

- Новый модуль `device/src/battery.h/cpp`, библиотека `adafruit/Adafruit
  ADS1X15` (новая зависимость в `platformio.ini`; PIO-имя пакета —
  `"Adafruit ADS1X15"` с пробелом, не `Adafruit_ADS1X15` — первая попытка
  добавить зависимость по логичному имени не нашла пакет в реестре).
- `initBattery()` — `Wire.begin(8, 9)` (те же дефолтные I2C-пины, что и в
  `wiring.md`), `ads.begin()`; если модуль не отвечает — не блокирует
  остальную прошивку, просто `batteryValid=false` в API.
- `updateBatteryReading()` — читает канал 0, кэширует в `batteryReading`
  (глобальная, как `trackList`/`groupList`). Вызывается раз в 10с из
  `loop()` вместе с heartbeat (не чаще — напряжение не скачет мгновенно, и
  не хотелось гонять I2C-шину из HTTP-хендлера).
- `GET /api/status` — добавлены поля `batteryValid`/`batteryVoltage`/
  `batteryPercent`. Не защищено мьютексом (в отличие от `trackList`) —
  осознанно: поле читается из AsyncTCP, пишется из loop(), но это два
  примитивных поля (float+uint8), максимум что грозит — на мгновение
  рассинхронизированная пара при чтении, для индикатора заряда это
  несущественно (тот же класс риска, что уже принят для
  `activeScenarioName`).
- Фронтенд — `components/BatteryIndicator.tsx` в шапке `App.tsx` (иконка +
  процент, `title` с точным напряжением и предупреждением "не
  откалибровано"). Свой опрос `useDeviceData()` в `App.tsx` — дублирует
  поллинг экранов, осознанный компромисс ради простоты (устройство
  локальное, лишний запрос раз в 2с не критичен).

`pio run`/`npm run build`/`test:run` (45/45) — зелёные. Живая проверка
показаний на реальной батарее (не USB-зарядке) — не делалась, числа
условны до калибровки (см. предупреждение выше).
