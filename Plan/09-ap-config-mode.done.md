# 09. Режим точки доступа (настройка)

**Статус:** done
**Обновлено:** 2026-08-11
**Проект:** device
**Зависит от:** 01

## Цель

Поднять собственную точку доступа (`WiFi.softAP`) вместо подключения к
домашней сети (в отличие от audio_test, который был в режиме STA с
захардкоженными кредами) — устройство самодостаточно, не зависит от
конкретной домашней Wi-Fi сети.

## Детали

1. `WiFi.softAP(ssid, password)` при загрузке, **если кнопка-защёлка
   физически замкнута** (GPIO2 = LOW, см. план 02) — режим AP определяется
   положением защёлки, а не отдельным программным флагом/событием. При
   старте (cold boot и после deep sleep) — сначала читаем уровень GPIO2,
   потом решаем, поднимать AP или продолжать сценарий (план 11).
2. SSID — что-то узнаваемое и не конфликтующее при нескольких устройствах,
   например `SpeakerCompact-<последние 4 байта MAC>`.
3. **Пароль AP — подтверждено, сеть защищена паролем.** Устройства без экрана
   — пароль должен быть узнаваем без подключения к серийному порту:
   - Простой вариант — фиксированный пароль константой в прошивке
     (`#define AP_PASSWORD "..."`), задокументированный в
     `device/docs/wiring.md`, пользователь помнит/печатает на корпусе сам.
     Подходит для одного/нескольких устройств "для себя".
   - Более аккуратный вариант (если планируется больше одного устройства) —
     детерминированный пароль из MAC-адреса (например, последние 6 hex-цифр
     `WiFi.macAddress()` + префикс) — уникален на устройство, не требует
     хранения секрета в прошивке, но пользователю всё равно нужно один раз
     считать пароль через Serial при первой прошивке, чтобы записать на
     корпус.
   Начинаю с фиксированного пароля (проще), переход на MAC-производный —
   по необходимости, не блокирует остальной план.
4. IP устройства в AP-режиме по умолчанию `192.168.4.1` (стандарт для
   `softAP` в arduino-esp32) — фронтенд обращается к этому адресу.
5. Тот же `AsyncWebServer`, что и в audio_test — раздаёт и фронтенд (план 16),
   и API (планы 04-08).
6. **LED-индикатор (GPIO15, план 02) включается вместе с AP** и гаснет при
   выходе из AP-режима (переход к сценарию/сну) — единственный видимый
   признак для пользователя, что устройство сейчас доступно для настройки.
7. **Автотаймаут AP — подтверждено, не нужен.** Защёлка — уже explicit
   контроль пользователя (в отличие от momentary-кнопки/подразумеваемого
   состояния), держим AP честно, пока она замкнута, без отдельного таймера.

## Открытые вопросы

- Нет.

## Критерии готовности

- Телефон подключается к AP устройства, видит фронтенд по `192.168.4.1`.
- Замыкание/размыкание защёлки во время работы (не только при старте)
  корректно переключает режим (см. план 11 про опрос GPIO во время сценария).

## Как реализовано

Был реализован ещё на этапе bootstrap (план 01), но файл плана никогда не
отмечался done — обнаружено и закрыто задним числом при разборе плана 10.
Всё по пунктам уже есть в `device/src/network.cpp`: `startAP()`/`stopAP()`
по состоянию `latchClosed()` (GPIO2), SSID `SpeakerCompact-<MAC>`,
фиксированный пароль (`AP_PASSWORD`, задокументирован в `wiring.md`), IP
`192.168.4.1` (дефолт `softAP`), LED на `PIN_AP_LED`, без автотаймаута.
`networkTick()` в `loop()` — не только на старте, полёт защёлки в реальном
времени (с дебаунсом 50мс, добавлен в эту же сессию после разбора шторма
`stopAP`/`startAP`).

Критерии готовности фактически подтверждены живьём в этой сессии
(реальный SSID, реальное переключение AP при отладке дребезга защёлки) —
отдельного HIL-прогона не делали, но это и есть тот самый HIL по факту.
