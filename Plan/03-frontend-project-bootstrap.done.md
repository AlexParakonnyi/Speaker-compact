# 03. Инициализация фронтенд-проекта

**Статус:** done
**Обновлено:** 2026-07-29
**Проект:** frontend
**Зависит от:** —

## Цель

Поднять React-проект в `frontend/` с нуля, готовый к разработке против IP
устройства (dev-режим) и к сборке в статику для заливки на SD (прод, см.
план 16).

## Детали

1. **Инструментарий:** Vite + React + TypeScript. ✅ Vite даёт быстрый dev-сервер
   с proxy на IP устройства (`server.proxy` в `vite.config.ts` -> `/api` на
   `http://<VITE_DEVICE_IP или 192.168.4.1>`), и лёгкую продакшн-сборку в
   статику (важно — итоговый бандл должен быть компактным, он живёт на SD
   встраиваемого устройства, не на CDN). Путь-алиас `@/*` -> `src/*` настроен
   и в `vite.config.ts`, и в `tsconfig.app.json`.
2. **Стек дизайна/анимаций** (мобильный экран — основной таргет, телефон
   подключается к AP устройства):
   - **Tailwind CSS — зафиксирован на v3.4** (не v4, который ставится по
     умолчанию через `npm install tailwindcss`), чтобы конфиг совпадал по
     формату с `Level-compact/front/tailwind.config.js` (CSS-переменные,
     `content`-глобы, `tailwindcss-animate`) — так копируемые компоненты
     `shadcn/ui` работают без переписывания под Tailwind v4. Конфиги —
     `tailwind.config.cjs`/`postcss.config.cjs` (`.cjs`, не `.js`, т.к.
     `package.json` имеет `"type": "module"` — иначе `module.exports`
     не грузится). Тема (CSS-переменные в `src/index.css`) скопирована из
     `Level-compact/front/src/index.css` для совместимости.
   - **shadcn/ui** (на основе Radix UI) — неплохой набор доступных
     (accessibility) компонентов для тайлов/диалогов/шитов, копируется в
     проект как исходники (не тяжёлая npm-зависимость), легко перекрасить под
     тему устройства. **Уже проверенный выбор** — родственный проект
     `Level-compact/front/` использует ровно этот стек с полным набором
     компонентов (`components/ui/*`); взять их за стартовую точку вместо
     установки shadcn с нуля, см. `CLAUDE.md` §8.
   - **Framer Motion** — анимации плиток (появление/исчезновение,
     drag-переупорядочивание в сценарии, свайпы), хорошо ложится на мобильный
     тач-интерфейс.
   - **vaul** (bottom sheet на Radix) — для мобильных модалок снизу экрана
     (редактор трека/сценария) вместо десктопных центральных диалогов.
3. **Структура проекта:**
   ```
   frontend/
     src/
       api/          — обёртки над HTTP API устройства
       components/    — переиспользуемые UI-компоненты (тайл, шит, кнопки)
       screens/       — экраны (список треков, редактор сценария, активация)
       hooks/         — React-хуки (useTracks, useScenarios, useDeviceStatus)
       lib/           — утилиты (ресайз картинки на канвасе, форматирование)
     vite.config.ts
   ```
4. **Никакого роутинга через react-router на старте** — экран/шаг сценария
   настройки, скорее всего, проще держать как локальный state одного экрана
   (wizard-подобный флоу: треки -> сценарий -> активация), учитывая, что это
   не многостраничное приложение, а конфигуратор одного устройства. Пересмотреть,
   если экранов станет много и понадобится глубокая навигация.

## Открытые вопросы

- Нужен ли офлайн-режим/service worker (PWA)? Не согласовано — вероятно, не
  нужен, раз фронтенд и так хостится с устройства и доступен только пока
  телефон подключён к его AP.

## Критерии готовности

- `npm run dev` поднимает dev-сервер с proxy на реальный IP устройства. ✅
  Проверено (порт 5183, `curl` на `/` вернул 200).
- `npm run build` даёт статическую сборку в `frontend/dist/`. ✅ Проверено
  (`tsc -b && vite build` — зелёно, Tailwind CSS реально генерируется, 5.4 kB).
- Пустой стартовый экран рендерится на мобильном разрешении без
  горизонтального скролла. ✅ `App.tsx` — `flex min-h-svh w-full`, без
  фиксированных ширин; визуально в браузере на реальном телефоне ещё не
  проверялось (нет доступа к устройству прямо сейчас) — перепроверить при
  первой live-отладке.
- Добавлен `components.json` (конфиг shadcn CLI) — не было в исходном плане,
  но пригодится в плане 12 при переносе/добавлении компонентов
  (`npx shadcn add ...` или ручное копирование из `Level-compact`).
