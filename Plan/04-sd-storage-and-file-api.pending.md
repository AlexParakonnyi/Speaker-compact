# 04. SD-хранилище и файловый API

**Статус:** pending
**Обновлено:** 2026-07-27
**Проект:** device
**Зависит от:** 01

## Цель

Перенести и адаптировать `storage.cpp`/`player.cpp` из audio_test под
"только воспроизведение" (без записи), плюс полноценный CRUD файлов:
переименование, удаление, перенос в группу (см. план 05).

## Детали

1. Перенести без изменений: WAV-заголовок на чтение (`parseWavHeader`),
   поддержку `.wav`/`.pcm`/`.mp3`/`.aac`/`.m4a` в списке файлов, числовую
   сортировку (`extractRecTimestamp` — тут, впрочем, файлы не создаются
   устройством, а заливаются с фронтенда, значит нужен свой способ
   сортировки/времени добавления, см. открытые вопросы).
2. Убрать всё про запись: `writeWavHeader`, `patchWavHeader`,
   `recordedBytesInSegment`, `startRecording`, `rotateRecordingSegment`.
3. HTTP API (через `pendingCmd`-очередь, как в audio_test — все мутации SD
   строго из одного места, см. `CLAUDE.md` §4.2):
   - `GET /api/tracks` — список треков с метаданными (имя, размер,
     длительность где посчитать можно, группа — см. план 05).
   - `POST /api/tracks/upload` — **подтверждено, загрузка аудио с фронтенда
     нужна** (не только через SD-картридер вручную). Нужны: лимит размера
     файла (проверять на устройстве, не только доверять фронтенду), список
     принимаемых расширений (`.wav`/`.mp3`/`.aac`/`.m4a`/`.pcm`), понятная
     ошибка при переполнении SD-карты или недопустимом формате.
   - `POST /api/tracks/rename`
   - `POST /api/tracks/delete`
   - `POST /api/tracks/clear_all` (как в audio_test — с подтверждением на
     фронтенде).
   - **`POST /api/tracks/play`** / **`POST /api/tracks/stop`** — превью
     воспроизведения выбранного трека прямо из браузера, пока активен
     AP-режим (новое требование). Переиспользует `player.h/cpp`
     (`startPlayback`/`stopAudio` из audio_test, см. план 01) — то же самое
     воспроизведение, что и в сценарии (план 08), просто вызванное вручную,
     а не по расписанию. Играть можно только один трек одновременно —
     повторный `play` останавливает предыдущий, как и в audio_test.
     Осмысленно только в AP-режиме (в режиме сценария вызывать неоткуда —
     AP выключен).
4. Раз файлы теперь заливаются с фронтенда (а не создаются устройством с
   именем `rec_<millis>.ext`) — нужна другая схема сортировки/времени
   добавления: либо хранить `addedAt` в метаданных (в том же файле, что и
   группы, см. план 05), либо просто сортировать по имени файла как есть.

## Открытые вопросы

- Нет — решение принято, загрузка с фронтенда нужна.

## Критерии готовности

- Список треков корректно отображается через API.
- Rename/delete/clear_all/upload работают без гонок (тот же паттерн `pendingCmd`).
- Загрузка с телефона аудиофайла отражается в списке треков без перезагрузки устройства.
