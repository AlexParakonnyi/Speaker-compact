# 16. Сборка и заливка фронтенда на устройство

**Статус:** in_progress (device-сторона реализована, см. ниже)
**Обновлено:** 2026-07-29
**Проект:** frontend + device
**Зависит от:** 01 (только storage/сервер из bootstrap, не весь фронтенд)

> ⚠️ **Несмотря на номер 16, реализовать сразу после плана 01** — этот
> HTTP-эндпоинт нужен с первого дня разработки фронтенда, чтобы не гонять
> SD-карту через картридер на каждое изменение. См. "Порядок выполнения" в
> `CLAUDE.md`.

## Цель

Процесс превращения `frontend/dist/` в файлы на SD-карте устройства, которые
раздаёт `AsyncWebServer` (согласованное решение — фронтенд хостится на самом
ESP32, `CLAUDE.md` §2.1). **Подтверждено: заливка через HTTP-эндпоинт**, не
вручную через картридер — пользователь явно попросил вынести это в начало
плана именно ради удобства отладки.

## Детали

1. `npm run build` в `frontend/` -> `frontend/dist/` (обычно `index.html` +
   `assets/*.js`/`*.css` с хэшами в именах).
2. **Эндпоинт `POST /api/deploy-frontend`** на устройстве — ✅ реализовано
   (`device/src/servers.cpp`):
   - Принимает файлы по одному: `POST /api/deploy-frontend?path=/www/assets/main.js`,
     тело — сырые байты файла (`ArBodyHandlerFunction`, не multipart/zip —
     проще на обеих сторонах). `path` обязан начинаться с `/www/` (проверка
     в `handleDeployBody`), иначе 400 — страховка от случайной перезаписи
     треков на карте.
   - Кладёт файлы на SD в `/www/<path>` через `storageBeginWrite/WriteChunk/EndWrite`
     (`storage.cpp`), раздаётся дальше через `server.serveStatic("/", SD_MMC, "/www/")`.
   - Доступен только пока активен AP-режим (естественное ограничение — вне
     AP этот HTTP-сервер и не поднят).
   - **Не через `pendingCmd`-очередь** — на практике для потокового
     multi-chunk body это неудобно (не атомарная команда). Вместо этого
     свой `sdMutex` (`global.h`), которым также защищено воспроизведение
     превью (план 04) в `loop()` — тот же принцип взаимоисключения SD-доступа,
     другой примитив. См. `CLAUDE.md` §4.2 (обновить формулировку).
3. **Важно: раздача с SD, не встраивание в прошивку** — в отличие от
   `index_html.h` (PROGMEM-строка) в audio_test, здесь React-сборка слишком
   велика для того, чтобы жить в flash-константе.
4. Учесть в `.gitignore` фронтенда — `dist/` не коммитить, только исходники.
5. `frontend/package.json` — npm-скрипт `deploy` (например
   `node scripts/deploy.js <device-ip>`), проходит по `dist/`, заливает
   каждый файл на устройство. Один шаг после `npm run build`.
6. Для справки: в `Level-compact` (родственный проект, см. `CLAUDE.md`
   §8) фронтенд деплоится через `pio run -t uploadfs` (LittleFS, требует
   USB-кабель) — рабочий паттерн, но не то, что нужно здесь: нужен деплой по
   Wi-Fi без кабеля, поэтому свой HTTP-эндпоинт, а не `uploadfs`.

## Критерии готовности

- Device-эндпоинт `/api/deploy-frontend` принимает файл и кладёт на
  `/www/<path>` — ✅ реализовано и собирается (`pio run`), но не проверено
  живьём на железе (нет ещё SD-карты/платы под рукой — план 17).
- `npm run deploy` (или аналог скрипт на стороне frontend) — ⬜ пока нет,
  появится вместе с планом 03 (frontend bootstrap).
- Собранный фронтенд открывается в браузере телефона по IP устройства в
  AP-режиме, без ошибок 404 на ассетах — ⬜ ждёт плана 03.
