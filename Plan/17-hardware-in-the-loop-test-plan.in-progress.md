# 17. План проверки на реальном железе

**Статус:** in-progress (частично закрыто по факту разработки; deep sleep/план 10-11 блокируют остальное)
**Обновлено:** 2026-08-11
**Проект:** device + frontend
**Зависит от:** все остальные пункты (сквозной чеклист, не блокирует их, но
подводит итог)

## Зачем отдельный пункт

Опыт `audio_test` показал: чистая компиляция ничего не гарантирует на
реальном железе — отсутствие общей земли, неверное выравнивание бит
микрофона, гонки между задачами, разряд AP-сети — всё это всплывало только
при тестировании на устройстве, иногда через несколько сессий отладки.
Здесь ставки выше (deep sleep, батарея) — нужен явный чеклист, не полагаться
на "наверное заработает".

## Чеклист (заполняется по мере готовности соответствующих пунктов)

Ниже — по факту живого тестирования в сессиях 2026-08-09 — 2026-08-11 (не
формальный отдельный прогон, а накопилось по ходу разработки фичей). Пункты,
блокирующиеся на планах 10/11 (реальных нет), оставлены неотмеченными —
это ожидаемо, не пропуск.

- [x] Базовая сборка (план 01) — `pio run` зелёный на реальном борде,
      прошивка заливается через UART-программатор, `Serial` лог читается
      (использовалось многократно на протяжении всей разработки).
- [x] SD-карта монтируется, список треков корректный (план 04) — включая
      находку и фикс гонки `trackList` (мигание/фантомы в UI после upload).
- [x] Группы создаются/сохраняются (план 05) — проверено вживую
      (группа "Главная", назначение треков). Переживание перезагрузки —
      прямо не проверялось отдельным тестом, но SD-карта не перезаписывается
      при обычной прошивке, и группа продолжала отображаться корректно после
      нескольких последующих переливок прошивки в этой же сессии — косвенно
      подтверждено, не строгий тест.
- [ ] Фото трека грузится с телефона (все три источника: буфер/камера/файл),
      отображается после перезагрузки устройства (план 06) — **не
      проверялось живьём**, только `npm run build`/`test:run`.
- [x] Сценарий проигрывается корректно на реальном железе (план 08,
      интерим-версия без deep sleep) — пользователь подтвердил "всё
      работает" после теста через фронтенд. Именно 3+ шагов с разными
      задержками/громкостью не подтверждено отдельно — базовый флоу (play →
      delay → следующий трек, пауза-шаг) проверен.
- [x] AP поднимается, фронтенд открывается на телефоне/ПК по `192.168.4.1`
      (план 09) — использовалось непрерывно всю сессию, включая отладку
      дребезга защёлки (нашли и починили debounce) и TX-мощности.
- [ ] Активация: AP гарантированно отключается после ответа фронтенду, не
      раньше (план 10) — **не применимо пока**, реального отключения AP нет
      (интерим-движок плана 08 держит AP активным, см. `CLAUDE.md` §10).
- [ ] Deep sleep — план 11 не начат, пункт неприменим до его реализации.
- [ ] Кнопка будит устройство из глубокого сна — план 11 не начат.
- [ ] Состояние сценария переживает цикл сон/пробуждение — план 11 не начат.
- [ ] Замер реального энергопотребления — план 11 не начат (сейчас
      интерим-движок и не экономит батарею, измерять пока нечего).
- [ ] Полный E2E-флоу с реального телефона (плитки → фото → сценарий →
      активация → срабатывание → возврат кнопкой) — частично: сценарии без
      фото проверены, полный флоу с фото и с реальной активацией (план
      10/11) — нет.
