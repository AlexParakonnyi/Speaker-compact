# Распиновка — Speaker-compact (ESP32-S3-N16R8)

> Плата ещё не разведена физически — это предложенная распиновка (см.
> `Plan/02-hardware-schematic-and-pinout.pending.md`), ждёт подтверждения
> пользователем перед разводкой. Пины подобраны по образцу подхода
> `Level-compact` ("использовать пины по умолчанию для своего чипа"), но
> **сами номера — не копия**: у `Level-compact` классический ESP32
> (`esp32dev`), у Speaker-compact — ESP32-S3, у них разные пины по умолчанию
> и разная карта зарезервированных GPIO (strapping/PSRAM/USB). Перенесён сам
> принцип, не конкретные цифры.
>
> Фото используемых модулей — в этой же папке (`docs/*.webp`).

## Усилитель MAX98357A (I2S TX, "I2S Mono Amp") → I2S_NUM_1

Тот же усилитель и та же распиновка, что и в `audio_test` (подтверждено
пользователем). Фото — `MAX98357 I2S 3W Class D Amplifier Breakout.webp`.

| MAX98357A | ESP32-S3 GPIO | Комментарий |
| --- | --- | --- |
| GND | GND | — |
| Vin | 5V (или 3V3) | — |
| DIN (Data In) | GPIO41 | как в audio_test |
| LRC (Left/Right Clock) | GPIO47 | как в audio_test |
| BCLK (Bit Clock) | GPIO21 | как в audio_test |
| SD/GAIN | не подключать | default 9dB gain, (L+R)/2 out (см. шелкографию платы усилителя) |

## SD-карта (SPI-режим) — обновлено под реальный купленный модуль

**Важно, изменилось относительно первой версии этого документа:** физически
купленный модуль — обычный `TF Micro SD Card Module` (6-контактный SPI-брейкаут
для Arduino/AVR, фото `TF Micro SD Card Module for ArduinoARMAVR.webp`), а не
модуль с нативным SDIO-выходом. Такие модули рассчитаны на SPI-библиотеки
(`SD.h`) — у них нет причин доверять пассивной подтяжке DAT3/CS, нужной для
надёжного `SD_MMC` (1-бит), поэтому вместо `SD_MMC` используем `SD.h` + `SPI.h`.
Для наших объёмов данных (моно 16-бит WAV на 16 кГц ≈ 32 КБ/с, плюс редкие
JSON/деплой-запросы) SPI с большим запасом быстрее, чем реально нужно — это не
компромисс по факту, просто соответствие реальному железу.

Пины — стандартные для `esp32-s3-devkitc-1` (совпадают со значениями в
`pins_arduino.h` этого борда), поэтому `SPI.begin()` без аргументов уже
собирает нужную распайку:

| Модуль (маркировка) | ESP32-S3 GPIO | Функция |
| --- | --- | --- |
| CS | GPIO10 | Chip Select |
| MOSI | GPIO11 | SPI TX (Master Out) |
| MISO | GPIO13 | SPI RX (Master In) |
| SCK | GPIO12 | SPI Clock |
| VCC | 3V3/5V (по модулю) | смотреть маркировку регулятора на плате модуля |
| GND | GND | — |

```cpp
#include <SPI.h>
#include <SD.h>

SPI.begin(12 /*SCK*/, 13 /*MISO*/, 11 /*MOSI*/, 10 /*CS*/);
SD.begin(10 /*CS*/);
```

## I2C-шина — ADS1115 (измерение заряда батареи) + резерв под TCA9548A

Новое: модуль `ADS1115 Four 16-bit ADC Module, I2C` (компактная версия — на
плате всего 4 пина V/G/S/D + 4 канала входа, фото
`ADS1115 Four 16-bit ADC Module, I2C.webp`) читает напряжение батареи через
делитель напряжения на один из каналов (0-3). Измерение заряда — то есть
чтение уровня, не управление зарядкой/BMS — попадает в зону ответственности
прошивки; сама схема заряда/защиты батареи по-прежнему вне зоны ответственности
этого проекта (проектируется пользователем отдельно).

По аналогии с `Level-compact` (там I2C на пинах по умолчанию для классического
ESP32 — GPIO21/22 для `Adafruit LSM303`/`Adafruit INA219`) здесь используются
**пины I2C по умолчанию для ESP32-S3** (не те же номера — другой чип, другая
таблица дефолтов; GPIO21 к тому же уже занят под BCLK усилителя):

| Модуль | ESP32-S3 GPIO | Комментарий |
| --- | --- | --- |
| ADS1115 — S (SCL) | GPIO9 | default I2C SCL для `esp32-s3-devkitc-1` |
| ADS1115 — D (SDA) | GPIO8 | default I2C SDA для `esp32-s3-devkitc-1` |
| ADS1115 — V | 3V3 | модуль на 3.3-5V, ориентироваться на логику 3.3В ESP32 |
| ADS1115 — G | GND | — |
| ADS1115 — 0..3 | (аналоговые входы ADS1115, не ESP32) | канал 0 — делитель напряжения батареи, 1-3 — резерв |

```cpp
#include <Wire.h>
Wire.begin();  // на esp32-s3-devkitc-1 по умолчанию SDA=8, SCL=9 — как и SPI выше, без явных аргументов
```

**Расширение через TCA9548A (I2C-мультиплексор, 8 каналов) — если потребуется:**
не требует дополнительных GPIO вообще — сидит на той же паре SDA/SCL (GPIO8/9),
разруливает адресные конфликты на уровне протокола (переключение каналов
командой по I2C), а адресные пины A0-A2 самого TCA9548A обычно распаиваются
намертво на GND/VCC для фиксированного адреса, не заводятся на ESP32. То есть
добавление мультиплексора **не меняет распиновку**, только логику инициализации
в прошивке (актуально, если один из будущих модулей будет с фиксированным
I2C-адресом, конфликтующим с уже занятым).

## Кнопка-защёлка (режим настройки/сценарий)

Механическая защёлка — замыкает и держит контакт до повторного нажатия
(не momentary-кнопка). Определяет режим устройства напрямую (замкнута = AP,
разомкнута = сценарий), а не просто "будит из сна".

| Функция | ESP32-S3 GPIO | Комментарий |
| --- | --- | --- |
| Защёлка | GPIO2 | `INPUT_PULLUP`, замкнута = LOW. RTC-GPIO, обязателен для `esp_sleep_enable_ext0_wakeup()` |

## LED-индикатор точки доступа

| Функция | ESP32-S3 GPIO | Комментарий |
| --- | --- | --- |
| LED (AP активен) | GPIO15 | Активный уровень HIGH, через резистор. Горит только пока поднят AP |

## Зарезервировано / не трогать (ESP32-S3-N16R8)

| GPIO | Причина |
| --- | --- |
| GPIO33–GPIO37 | Octal PSRAM (SPI IO4-7) — фиксировано модулем N16R8 |
| GPIO0, GPIO3, GPIO45, GPIO46 | strapping-пины (режим загрузки) |
| GPIO19, GPIO20 | native USB (USB_D-/USB_D+) |
| GPIO43, GPIO44 | UART0 (TX0/RX0) — держать свободным под серийный монитор |

## Питание/батарея

Схема заряда/защиты батареи (BMS) — вне зоны ответственности этого документа,
проектируется пользователем отдельно. **Измерение уровня заряда** — в зоне
ответственности прошивки через ADS1115 (см. выше), т.к. пользователь явно
добавил этот модуль в проект.
